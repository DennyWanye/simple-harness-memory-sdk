## 调用接口

在本 worktree 根目录使用 Python 3.11–3.13 标准库，无需安装 SDK 或连接 Provider。模块入口如下；实际验收以Python 3.12.14通过共享资源入口执行，完整命令见结果文档：

```sh
python3 -m scripts.corpus_runtime_input
```

可选 `--source <MD目录>` 和 `--output <新目录>`。源目录必须满足 r4 原成员及索引字节指纹，不提供跳过校验选项。输出限本 worktree 已忽略的 `.local-test-evidence/` 内，默认 `.local-test-evidence/corpus-runtime-input/successor-12x20-r4-20260906/`；目录已存在即拒绝，不能覆盖或混入旧结果。所有文件准备完成后才开始写入，manifest 最后写；I/O中断可能留下未完成目录，不能作为完成批次。

| Python 接口 | 用途与边界 |
|---|---|
| `compile_source(source: Path) -> dict[str, bytes]` | 校验指纹、解析明确字段并返回全部输出字节；不写文件、不运行 SDK |
| `parse_document(filename, text) -> tuple[Case, ...]` | 严格字段解析原语，供后续内存内变异验收；不提供 CLI 指纹绕过 |
| `write_artifacts(artifacts, output)` | 将编译结果写入全新 ignored 目录；不产生执行状态 |
| `project_authored_conversation(value: InitialInput) -> list[dict[str, str]]` | 仅投影明确的角色、历史与当前用户句；拒绝未拆分的可信上下文；不是 Provider 调用接口 |

`contracts.py` 只定义时钟、初始输入、历史和后续轮类型，不导入 compiler、setup 或 oracle。投影函数只接受 `InitialInput`，没有接收整条 Case 或任意计分字典的入口。编译器/审计进程能够读取完整语料，这不是操作系统级隔离；后续 Provider 进程必须只拿经运行适配审核后的最小请求，不得读取完整编译目录。

## 输出分区

JSON采用 UTF-8、键排序、紧凑编码和一个结尾换行，不包含生成时间、随机值或绝对工作路径。JSONL各分区固定一条逻辑样例一行，按 C01-01 至 C12-20 的顺序对应；关联信息仅在独立目录中，不能把整个文件行直接当 Provider 请求。

| 文件 | 内容及消费者 |
|---|---|
| `input/initial-input.jsonl` | 240组输入计划：`scenario_clock`、`recent_messages`、`current_user_message`、`unresolved_source_text`；输入适配器读取 |
| `setup/cases.jsonl` | 原 setup 语句、时钟及原声明、缺口；`seed_operations=null`、`public_setup_state=NOT_IMPLEMENTED`、`ready=false`、`executed=false`；设置端读取 |
| `setup/common.json` | 独立总索引中的默认时钟和统一政策原文；仍待真实 Host 配置与投影，`authority_receipt=null` |
| `scheduler/cases.jsonl` | 240组固定脚本，C05合计22条，其余为空；只有后续真实调度器读取 |
| `oracle/cases.jsonl` | 原类别继承标签及每条完整 gold 文字；仅计分端读取，事实判定未实现 |
| `audit/catalog.jsonl` | 行号、ID、类别、独立语义条件、源文件和行号；协调/审计端读取 |
| `audit/source-documents.json` | 完整14份源文档文本，保留所有未结构化说明及格式，含 gold；仅审计端读取，禁止用于模型 Context 或设置授权 |
| `manifest.json` | 原成员、索引、编译器及输出字节指纹、类别计数和 `SOURCE_ONLY / BLOCKED_PUBLIC_ADAPTERS / NOT_RUN`；不能给模型 |

类别标签完整保留在 oracle，类别名称在 catalog；它们不进入输入字段。硬限制与隐私结果仍需真实 trace，不将零查询折算为后台 gate 已测。此层没有模型类型预测、阈值判定或 PASS 生成能力。

## 字段映射

普通单句初始输入只取明确 `provider_input` 字段。C05只取 `provider_input_first_turn`，scripted_followup独立存放。C07-06/14分别提取 `recent_messages` 表中显式 ordinal/role/content 和 `current_user_message`，保留数组；后继适配器必须通过真实历史入口建立已提交因果组，再由 Context assembler读取，不能将本模块的纯消息投影当作已经验证的最近历史链。

时钟来自设置字段：C04各条解析显式 `scenario_clock`，其余采用独立总索引的共同 fixture。C04-15为 `2026-09-30T18:00:00+08:00`，其余为 `2026-09-06T10:00:00+08:00`，均 `Asia/Shanghai`。仅检查声明偏移与时区一致；未来事件 trigger 的换算和 eligibility 不在这里执行。后续必须将同一时钟接到真实 Host clock、SDK as_of/evaluated_at及 Provider可信日期入口，不能从 gold 生成系统提示。

以下输入不能安全地直接投影为用户消息，保留在 `unresolved_source_text`，`current_user_message=null`，投影时明确报错：

- C12全部20例：同一字段混合“受众/用途/公开资料”和“用户”语句。需要后续独立、逐例明确的可信上下文与用户字段绑定；本层不靠分号、自然语言标签或 gold 猜 SDK enum、政策权限及角色。
- C05-07：同一字段含“可信Host当前任务/实际scope快照”和用户句。需要真实任务绑定快照及明确用户消息，不把文字说明提升为授权。

这些是待适配的21组输入，不是丢弃样例或改变分母。其余219组纯消息投影即使能构造，也因公共设置未实现而不可执行。

## C05 固定后续轮契约

每条保留 `followup_id / after_event / fixture_action / user_message / on_unmet`，按源表行序调度。20个逻辑样例仍是20，不计为42。C05-16及C05-20各有f1/f2，其余只有f1。

| 事件/动作 | 后续适配器必须满足的事实 |
|---|---|
| `candidate_preview_then_turn_terminal` | 真实非空、schema及reader披露来源合格的候选返回，首轮结束；无正式resume receipt/新增执行授权；不以包含gold目标为条件 |
| `new_candidate_preview_after_f1_then_turn_terminal` | f1之后出现新的合格候选并结束该轮，保留之前trace |
| `assistant_turn_terminal_after_f1` | f1对应助手轮结束，仍无正式resume/新增授权；无需新增搜索 |
| `append_predefined_current_revision` | C05-18由真实公共fixture接口追加setup已定义的新revision；无此能力则阻断，不能造receipt |
| `record_unmet_and_stop_no_rescue` | 前提不满足则记录真实原因、停止该例；不救场、不补gold提示、不移除失败样例 |

允许搜索内部open返回经reader过滤的scope_disclosure；禁止完整未过滤档案。正式resume授权与内部预览分开判断。编译器仅校验上述显式枚举、顺序和表结构，没有模拟这些真实事件或运行scheduler。
