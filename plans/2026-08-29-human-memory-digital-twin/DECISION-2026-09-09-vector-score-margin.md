# 裁决：认知向量通道的阈值策略——`COGNITIVE_VECTOR_MIN_SCORE = 0.45` 对中文短记忆没有余量

> 2026-09-09。用户委托裁决，不再征询：本备忘给出测量、裁定、落地与边界，0.6.34 候选实现。
> 依据契约 S3 Task 5（`slices/S3-cognitive-systems-recall.md`）、
> `DECISION-2026-09-07-cognitive-vector-lane.md` §4.1 的阈值理由与 §4.4 的「冷态只退化不失败」。

## 0. 一句话结论

**采纳方案 (b)：阈值改为「同一记忆类型内的相对判据 + 绝对护栏」**，绝对阈值 0.45 **一个字节不动**
（只作为准入上界保留），新增两个冻结参数 `COGNITIVE_VECTOR_RELATIVE_FLOOR = 0.35`、
`COGNITIVE_VECTOR_RELATIVE_RATIO = 0.90`。方案 (a) 被实测**证伪**（不存在这样的常数），
方案 (c) 被实测**证伪**（中文同义改写的词面重叠为 0 是常态）。

生效下限（`features/cognitive_vector.cognitive_vector_effective_min_score`）：

```
effective(type) = min(0.45, max(0.35, 0.90 × 该类型内已过全部资格门的最高余弦))
准入 ⟺ cosine ≥ effective(type)
   ⟺ cosine ≥ 0.45  或  （cosine ≥ 0.35 且 cosine ≥ 0.90 × 该类型最高分）
```

因为 `effective ≤ 0.45` 恒成立，**0.6.33 下已经进入 `vector` lane 的候选，在 0.6.34 下全部仍然进入**；
本次改动只可能把原本被拒的候选放进来，不可能把原本准入的候选挡在外面（pin，§6）。

## 3. 三个方案的裁定

### (a) 只下调常数 —— **不可行（实测证伪）**

任务给的判据是「取一个值，下方与同义改写下界留 ≥ X 余量、上方在无关上界之上」。
按 §2，同义改写下界 0.0601 **低于**无关上界 0.6251，二者之间**不存在**任何这样的值：
X 的可行域为空。硬要靠单一常数把 C06-06 的 0.3690 救回来，就得把阈值压到 0.35 附近，
代价是无关准入从 3.74% 涨到 21.85%（约 6 倍），这会直接冲击 C07 零召回子集与"多提"指标。
**因此 (a) 不采纳**——但它的测量是 (b) 的地基：绝对护栏 0.35 正是这条扫描给出的。

### (c) 保持 0.45、让 Host 词面通道兜底 —— **不采纳（实测证伪）**

判据是"零词面重叠的中文改写是否常见"。三例 FAIL 的存储 payload 与模型查询的
`typed_recall_query_terms`（`\w` 词项 + CJK 二字组）交集**全部为空**：

| 用例 | 存储向量文本 | 模型实际查询 | 词面命中 |
|---|---|---|---|
| C01-19 | `user:self / explanation order / 先说结论再说理由` | 说明事情时先报结果还是先铺背景？用户的表达习惯/偏好 | 0 |
| C06-06 | `user:self / 图表说明 / 要配文字说明` | 培训材料的可访问性要求、格式和检查流程 | 0 |
| C06-08 | `user:self / 方案说明顺序 / 先结论` | 全局表达要求与比较方法（采购对比框架的格式与规则） | 0 |

注意 C06-06 / C06-08 的 predicate **本来就是中文**——评审表推测的"英文 predicate 稀释"
只解释得了 C01-19 一例，另两例是纯粹的中文同义鸿沟（"图表配文字说明" ↔ "可访问性要求"、
"方案说明顺序=先结论" ↔ "全局表达要求与比较方法"）。词面通道对这类改写结构性地无能为力。
0.6.22 备忘 §2 已记录过同族反证：C01-06 四种、C01-17 六种改写全部 0 命中。
**因此 (c) 不采纳。**

### (b) 相对判据 + 绝对护栏 —— **采纳**

同一无关准入水平下，相对判据的目标召回严格优于纯绝对阈值（下表为并库扫描，
union 形式 `s ≥ 0.45 或（s ≥ FLOOR 且 s ≥ RATIO × 同类型最高分）`）：

| 策略 | 目标召回 | 无关准入 | 每次召回准入数 |
|---|---|---|---|
| 绝对 0.45（0.6.33 基线） | 83.8% | 3.74% | 4.82 |
| 绝对 0.42 | 86.6% | 6.25% | — |
| **union，FLOOR 0.35 / RATIO 0.90（本次采纳）** | **87.2%** | **4.01%** | 5.13 |
| union，FLOOR 0.35 / RATIO 0.85 | 88.0% | 4.32% | 5.44 |
| union，FLOOR 0.35 / RATIO 0.80 | 88.9% | 5.00% | 6.10 |
| union，FLOOR 0.30 / RATIO 0.70 | 91.5% | 9.49% | 10.44 |

采纳档比基线**多召回 3.4 个百分点，只多准入 0.27 个百分点的无关记忆**，
每次召回的候选数从 4.82 升到 5.13（`lane_cap` 与预算裁剪不变）。

**两个参数的取值理由**

- `RELATIVE_RATIO = 0.90`：只救援"该类型内与最佳并列"的候选。它是"救援"而不是"降低阈值"——
  落后该类型最高分 10% 以上的候选一律不进。0.85 / 0.80 的召回收益（+0.8 / +1.7pp）
  换来的无关准入涨幅（+0.31 / +0.99pp）与候选膨胀不成比例，故取 0.90。
- `RELATIVE_FLOOR = 0.35`：**整库都不相关时不救援**的绝对护栏，是 C07 零召回子集的唯一保护。
  它比无关分布的中位 0.2818 高出 0.067；同时它是**能覆盖 C06-06 目标（0.3690）的最大整值**——
  取 0.38 就救不回 C06-06（0.3690 < 0.38），取 0.30 则在无关分布 p75（0.3455）之下、护栏形同虚设。

**相对参照必须按记忆类型分组**（本次裁决最关键的结构选择）。C06-06 的形状是
episode/procedure 侧 0.6017 与 semantic 侧 0.3690 同处一次召回：若参照全局最高分，
semantic 的下限会被推到 0.5415，目标必然落空；按类型分组后 semantic 以自身最高分为参照被救回。
这与既有实现同构——lane 排序与预算本来就是 `for memory_type in requested_types` 分组做的；
也直接服务于"多提类型 ≤ 15%"：类型是模型选的，一个类型的强匹配不该压掉另一个类型的最佳匹配。

## 5. 与既有契约的关系

- **S3 Task 5 的资格门顺序、四条既有 lane 的计分、RRF 权重、`lane_cap`、预算裁剪**：一字不变。
  向量比对仍然只发生在**全部资格门（状态/类型权威/血缘/抑制/scope/entity/时间/disclosure）之后**，
  被抑制或遗忘的记忆永远不参与比较，也永远不进入"该类型最高分"的计算。
- **`DECISION-2026-09-07` §4.4「冷态只退化不失败」**：本次不触碰任何退化路径。
  无 embedder / 无世代 / stale / 查询嵌入超时仍分别落
  `cognitive_vector_unavailable` / `_no_generation` / `_stale` / `_deadline`，词面 lane 照常。
  相对判据只在 lane 真的跑起来时生效；lane 没跑就没有"该类型最高分"，也就没有救援。
- **争议 group（0.6.31 槽位级准入）**：成员的 `vector` lane 用同一条规则，
  相对参照 = 两名成员与**同类型普通候选**的最高余弦；group 级的
  「成员必须不低于同类型任一普通候选」判据一字不变。
- **零 DDL**：schema 7.4 checksum 不变；世代身份、manifest、`COGNITIVE_TEXT_FORMAT_VERSION`、
  向量文本渲染全部不变——**已有库不需要重建世代**。

## 6. pin 边界（哪些字节变、哪些不变）

- **不变**：所有存储侧 hash（`content_hash` / `embedding_hash` / 世代 manifest / 血缘）、
  `decision_hash` / `result_hash` / `receipt_hash` / `public_result_hash` 的**计算方式**，
  以及判定不变的那些召回的这些值本身；根导出零增减；`COGNITIVE_VECTOR_MIN_SCORE` 仍是 0.45。
- **有意变化，且严格限定在"判定改变"与"审计"两处**：
  1. 原本低于 0.45、现在被救援的候选会进入结果——这正是本次修复的目的，
     其 `result_hash` 等自然随内容变化（与任何一次召回内容变化同理）。
  2. `typed_recall_terminals.terminal_json.cognitive_vector` 增加 `admission` 块
     （`min_score` / `relative_floor` / `relative_ratio` / 每个请求类型的 `effective_min_score`）。
     **阈值动态化后必须可审计**是任务的明确要求；该块只在 `cognitive_vector` 已存在时出现，
     即**只有真的跑了向量通道的召回**其终态 hash 会变，未请求 vector 的召回终态逐字不变。
     记录原始余弦有先例：短时域审计的 `vector_lane[].score` 本就是原始余弦。
