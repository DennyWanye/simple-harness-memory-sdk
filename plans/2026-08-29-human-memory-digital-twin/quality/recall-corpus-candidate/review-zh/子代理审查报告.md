## 优先处理的真实问题与建议

### R01｜高：这份候选集与现有质量指标配套语料不是同一评估集

本次文件是 24 family × 10 条，SHA-256 为 `e3d39fdf68ded5c4af94b7c7ca04587b724b46643d1ea6fd2ccecb0003e039d5`。Host 的 [语料规格](/Users/denny/projects/simple_harness/testcase/human-memory-program/fixtures/model-eval-corpus-spec.json) 是 12 类 × 20 条，且 [TC-HM-X01](/Users/denny/projects/simple_harness/testcase/human-memory-program/TC-HM-X01-contract-init-quality.md:17) 记录另一份生成语料的 hash `49e622f3e6913e870e08fbb58d5f21fb44226a2a63d1eec1ee7fb985e054a5a7`。后者的原始生成产物本轮未重建；上述 hash 是读取 testcase 的记录，不是本轮计算结果。

现有规格将 TaskScope 搜索单独计分，要求 `requires_task_scope_search`；候选集却把 `task_scope` 放入 `expected_required_types`，还把 `raw_evidence`、`short_horizon` 与四类长期记忆混在同一统计列。候选集 README 已正确说明它们不是额外的长期认知类型，但尚无到实际 evaluator 的明确映射。

**建议：** 主代理先确认候选集将作为补充集、替换提案还是独立评估集。明确长期类型、短时域、TaskScope、原始证据各自指标；不得因两份集都恰好 240 条就直接套用既有门槛或替换质量分母。本审查没有修改这些定义。

### R02｜高：50 条 NO_RECALL 同时要求召回类型，混淆零查询与零结果

受影响编号：091–120、141–160，共 50 条；分别为 suppression、两类 privacy、draft Procedure、terminal Prospective。这些题同时含 `expected_outcome=NO_RECALL`、非空 `expected_required_types`、空 selected refs。

[HM-AC-4](/Users/denny/projects/simple-harness-memory-sdk/plans/2026-08-29-human-memory-digital-twin/acceptance.md:67) 的 no-recall 要求“不查询记忆”，而查询后资格门过滤为空是另一条执行路径。当前文本无法表明 required types 指模型提出的通道、执行过的查询，还是最终送入 Context 的类型。[指标公式](/Users/denny/projects/simple_harness/testcase/human-memory-program/fixtures/metric-formulas.json:3) 也必须与这一层级对齐。

当前 required-type 总数为 260。如果按最终可见类型计分，50 个空结果类型不得分，即使另外 10 个冲突确认类型都给分，理论上也至多为 210/260≈80.77%，达不到 90%。这只是说明“直接这样映射会矛盾”，不是实际 evaluator 得分；本轮没有运行 evaluator。若改按模型提议计分，又必须防止通过提议禁止类型拿 required credit。

**建议：** 分开记录召回需要、允许查询的来源、查询后结果、最终披露、执行权限；对纯 no-recall 明确零 Memory query。对过滤题记录“查询/裁决后无可披露结果”，并明确 proposed types 与 delivered types 的计分方式，避免把合理过滤误判漏召回。

### R03｜高：20 条隐私拒绝题把“未授权”放在答案解释里，没有给出权威上下文

编号 101–110 的题面是“把我的 … 医疗偏好发给群聊”，属于明确发送请求；111–120 的题面直接请求广告画像用途。前者只有 group recipient，后者只有 `advertising_profile`；均缺原许可范围、接收者授权状态、策略版本或本轮请求能否更改策略的规则。`design_reason` 声称“未授权”或“不符合原始授权”，这不是独立输入证据。

这不意味着应当直接允许披露，而是**现有信息不能唯一支撑该 reason code**。不能把“敏感＋群聊”或用途词本身当成用户授权事实。

**建议：** 增加可信、明确的披露策略和授权快照，再标 DENY；另做已授权群聊/允许用途的最小对照。若规则要求独立确认，应标明该确认边界。补具体的虚构医疗/财务事实，替换“Atlas 医疗偏好”一类不自然占位。将群聊发送的操作授权与 Memory 内容披露许可分别审查。

### R04｜高：10 条冲突题保留“不选边”意图，但不能直接进入现有质量分母

编号 081–090 的上海/东京对立确实支持“不静默选一个值”。但题目只有问答，没有给出依赖该值的后续动作；fixture 只有两个 `lifecycle_status=contested`，没有独立 conflict status、共同事实键、完整 conflict group、成员 revision/hash 或 current-head 关系。“两个有冲突字样的 ref”不足以构造当前协议要求的完整确认 carrier。

[S3 规则](/Users/denny/projects/simple-harness-memory-sdk/plans/2026-08-29-human-memory-digital-twin/slices/S3-cognitive-systems-recall.md:242) 及 [TC-HM-X01](/Users/denny/projects/simple_harness/testcase/human-memory-program/TC-HM-X01-contract-init-quality.md:19) 明确：依赖冲突的 complete/partial 场景只进入确定性协议 oracle；质量集保留 contested-not-required 的 no-recall 类。当前 10 条不能当作该 20 条的等价替代，也不应机械改成 no-recall 来伪造一致。

**建议：** 单列为待主代理复核的冲突协议/语义案例；补“依赖区域才能继续”的任务与完整组，补一侧被 suppression、无权、过期及预算不足的对照。确认只允许完整、合格的组，不能泄露被过滤的另一侧，也不能将一侧作为普通 selected 返回。

### R05｜高：20 条跨类型题把“相关”直接升级成“必需”，70 条硬触发缺统一含义

编号 071–080 一律要求 semantic＋procedure＋prospective。题目只要求“规划下一步并照我的方式做”，偏好与方法有直接依据，月底复查预算虽相关，但没有证明必须纳入本轮。固定 now 是 2026-08-30 16:00 UTC，即上海时间 2026-08-31 00:00；确实接近月底，不能据此断言该意图无关，但题中仍没有到期时刻、时区、规划范围或事件依据来证明“必选”。

编号 231–240 的“开始发布”与“发布成功后提醒”是不同阶段。可以讨论在准备阶段读取 pending 意图作为计划信息，但不能把它算成已触发提醒。全 240 条 `event_constraints` 均为空，70 条 `hard_trigger=true` 主要来自发布、查询提醒、恢复任务、原话等用户意图，并非 70 个已证明发生的时间/事件硬信号。

**建议：** 对原题先区分 required 与允许但非必要的类型；若坚持三类必选，补明确依赖和阶段。拆分待办查询、提醒触发与动作执行，补“发布开始/成功/失败”“到期前/到期后”“无提醒需求”的最小对照。不改变既定阈值，但要先明确硬触发分母究竟统计什么。另补“模糊愿望仅 Semantic Goal、缺触发仅 candidate”的反例；当前集没有这些重要提醒边界。

### R06｜高：20 条工作上下文/近期召回题的关键前提没有进入输入

编号 201–210 要把“上一句”里的项目名加粗，却没有上一句；空 selected 不能证明模型能正确完成改写。编号 051–060 在理由中称“五分钟前”的记录位于最近十组之外，但没有最近十组、角色顺序、Context 可见 refs 等依据。五分钟前也可能仍在当前 Context，应直接回答而不用查询。

编号 211–220 同样需要说明“昨天的端口决定”已经不在当前 Context。另有 051–060 的 valid_from 到 valid_to 相差 5 天加 300 秒：若这些字段用于模拟短时域生效/到期，会比发生时刻起五天多保留五分钟；若不是此语义，就不能用它们声称覆盖五天边界。

**建议：** 给出模型真正可见的最小对话窗口和 Context refs，区分“已在工作上下文”与“窗口外但五日内”。直接使用 occurred_at/expires_at 或声明精确映射；增加第 10/11 组及五日内/外的对照。

### R07｜高：10 条 draft 程序题混合状态、隐私和执行许可，漏掉相关安全事实

编号 141–150 的 draft 自动删除程序 a 不应作为可执行流程，这一点可保留。但同题还有 active semantic b“删除具有高风险”，题面又要求直接执行；可以合理召回 b 解释风险或要求确认，整体 NO_RECALL 并不唯一。将 `lifecycle_status_gate` 放入 `expected_privacy_outcome=DENY`，还会把程序资格拒绝混入隐私禁止项指标。

编号 031–040 虽然程序 active，但缺当前环境/版本适用性与明确确认来源。active 可支持“候选程序有效”的抽象设定，不能证明生产部署已经获本轮执行授权。

**建议：** 分别断言程序不可用、风险语义是否需要、披露是否允许、删除/发布动作是否获权。程序召回通过不等于动作可执行；用户说“按我的流程来”也不能替代数据里缺少的程序适用性。补齐规则后由主代理复核最终标签。

### R08｜中：240 条题目只形成 24 个措辞模板，50 条具备可保留的清晰意图

所有 query 按原文计数确为 240 个不同字符串；只替换实体名并去除题尾编号差异后恰好为 **24** 个模板。每组 10 条主要变化为项目名、ID、task phase/current scope 轮换；端口组另按序号变化端口值。没有因这些变化而产生新的标签。把同组拆进不同评估批次也不能获得独立语义覆盖。

最明显的是 001–010 的“编号 0…9”，101–120 的“项目名＋医疗偏好/财务信息”，以及所有组固定采用明显的召回提示词。部分干扰候选直接写“无关”“另一个项目”“旧”“次要”，不需要细致语义判断即可排除。

**建议：** 保留 5 组共 50 条的基础标签方向（见下表），但仍需去重与轻修；每个 family 补口语、省略、指代、无路由关键词和最小反事实，不以换实体凑条数。可按 family 汇总诊断，并明确任何补充统计不是替代现有正式指标。

## 不能用于质量结论的缺口

1. 本轮只有静态语料审查，没有真实主模型逐条预测、独立两轮 root runs、调用次数、失败计分或逐项分子分母。已有结构 validator 输出仅为 `VALID_AI_DRAFT_ONLY`。
2. AI 草稿状态仍为 `AI_DRAFT_UNREVIEWED` / `NOT_RUN/BLOCKED`。主代理复核本报告也不自动等价于用户/独立人工完成标签确认，更不等价于冻结后的真实评估。
3. 240 条、470 个 fixtures 不代表 240 种独立语义情境。缺口包括无关冲突无需确认、一侧冲突无权、明确纠正与含糊更新对照、模糊愿望/缺触发、发布失败不提醒、取消/重排/重复事件、允许接收者/用途、跨主体同名记忆、已忘原文受控审计等。
4. 默认 4096 bytes/900 tokens/4 items 和一组 512 bytes/100 tokens/1 item 不是实际 Provider Context 预算证明；没有冷/热延迟、成本、100k 检索或 deadline 实测。
5. fixture/label 不能全部预先作为路由模型可见输入：`family`、`design_reason`、`expected_*`、含类型的 scenario/ref 名称可能泄露答案；被 suppressed/禁止披露的正文更不能先塞入模型 Context 再用“未选中”证明隐私。正式 evaluator 需明确 Host 输入、库内 fixture、模型可见 payload 与 scorer gold 的边界。本轮没有发现/验证实际 evaluator 已发生这种泄漏，仅指出尚缺输入隔离说明。
6. 本轮不替代主代理独立开展的 native、Host 生产链和 UI 审计；未对真实故障率、权限执行、遗忘后的重建路径或提醒调度可靠性作 PASS 声明。

## 核查方法、来源与交付边界

辅助只读核查为 JSON 解析、文本/字段计数、SHA-256 与现有 `validate_corpus.py`；未运行生成器，未重写 corpus/manifest。原始统计为：RECALL 160、NO_RECALL 70、NEEDS_USER_CONFIRMATION 10；hard_trigger 70；隐私字段 ALLOW 200 / DENY 40。40 个 DENY 包含 suppression 10、接收者 10、用途 10、程序状态 10，不能直接称为 40 条纯披露授权测试。
