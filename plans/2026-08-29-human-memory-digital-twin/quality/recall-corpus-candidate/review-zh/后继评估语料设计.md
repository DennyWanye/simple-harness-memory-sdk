## 可执行的输入与 gold 隔离契约（待适配实现）

后继每条逻辑记录分四部分，实际运行时分离加载；不把整个 record 序列化给模型。

| 部分 | 内容与可见性 |
|---|---|
| setup | 评估端建立事实、状态、适用性和权限；库内记录正文、revision、suppression 等不直接进入模型。只补判断所需字段；生产 receipt 由公开 seed/adapter 取得，不在每条语义题伪造 |
| provider_input | 白名单仅包括固定任务规则、独立可信的受众/用途政策、必要当前日期时区、最近实际对话/当前任务、query、正式工具 schema。无 query_id、class、variant、design_reason、gold、期望 refs 或含类别的内部 ID |
| oracle | 原 gold、必需事实、允许/禁止来源和可接受行为，只有计分器可读。此 MD 中披露库内测试值是为评审，MD 本身不能作为 Provider 输入 |
| trace | 路由计划、工具调用、资格裁决、真实返回载荷、最终 Context/回答与使用来源、query count、延迟、失败原因、模型/Provider 身份；敏感 fixture 值只用本地虚构内容且原始 trace ignored |

setup 通过隔离的公开 seed 入口建立测试状态；seed 完成后清空运行侧预加载 Context，再从 provider_input 开始计数。不能预先查出答案再塞进“工作记忆”。S01–S06 的必需事实均不在初始可见 Context；只有实际合格工具返回后才可见。S08–S12 的禁止正文在初始输入及任何工具返回中均不可见。受众政策来自独立 Host 配置，不从 `privacy_allowed` 布尔值反推；同一政策也应用于正向任务，避免按类别特设提示。

适配器未实现前不能宣称模型看到的就是此契约；也不能因隔离尚未证实而请求用户重新安排真人。未来的无模型检查最少包括：序列化 Provider 输入的字段白名单断言；替换全部 gold 后输入字节/hash不变；替换不相关隐藏记录后初始输入不变；保留相同公开政策分别装载有/无禁止记录以检查不存在性泄漏。种子内容只能通过正式工具资格门进入后续载荷。

## 计分实现必须明确的口径

原公式未指定所有 trace 到 prediction 的细节；以下是建议映射，待主代理复核后作为后继版本附件固定，不声称现有 runner 已如此工作。

1. predicted_types 仅取本轮真实 Provider 结构化提议的长期类型集合，每条按类型去重；当前固定类型接线未补齐前，此量不可由 Host 集合代填；四类之外的 TaskScope/short/raw 不混入此集合。matched_required_types 仅计既被正确提出、又由合格来源实际交付且满足本题必需事实的 gold 类型，禁止仅靠报出类型名拿分。extra 用 proposed_types 减 gold_required_types；非法计划依原 spec 将拒绝前提出的全部类型计为 extra，不能因 SDK 拒绝抹掉过度请求。
2. no-recall 必须完成该题允许的直接回答/拒绝，并有零检索调用、零记忆查询、零 page-in/原文读取/任务搜索、零记忆引起的额外模型续调。计数从首个 Provider 请求开始到终态；公共策略预置和 seed 不计作请求内查询，但不能借此预取 gold。正常路由记录/纯权限裁决不是记忆检索。
3. privacy/hard correctness 要核对真实载荷、最终 Context 与回答不含或依赖禁止来源，且执行该样例规则。未提供 trace 或未执行不能按“空输出”记正确。隐私泄漏判断以明确禁值、语义等价披露及来源使用为准，仅字符串 canary 零命中不足。
4. timeout、refusal、invalid-plan 和重复操作沿原 spec；timeout 计错且无 required credit。只有 gold=no-recall 且确无查询时，refusal 才可按原政策允许。所有失败都留在适用分母，不删题；观察到“零泄漏”也不将失败尝试自动转换为整体通过。
5. TaskScope 单列 search→受控候选预览→用户消歧→正式 exact resume 的 trace。搜索内部的 open 不是恢复授权，不能一律判错；首轮禁止正式 context_route resume receipt 和新增任务执行授权，禁止完整未过滤档案。样例可含确定的第二条用户输入，但必须在模型真正返回候选后才送入，不能把正确 exact ID预塞到首轮。统计为一个逻辑样例，第二轮 root 重新执行。搜索失败时仍使用冻结的样例脚本/稳定失败条件，禁止临时提示答案。
6. 每条除六项原指标外，还记录必需内容、禁止内容和行为是否正确，作为可复核诊断。此附件明确匹配/错误的定义，不增改百分比门槛。S01–S06 错选同类型 ref 不能仅凭类型一致宣告该题成功。

### 零查询与后台裁决的证据不能互相替代

S08–S12 中的 hard/privacy 是待验证 gold 条件，不是根据类别或零查询派生出的实测结果。每次真实运行至少分别记录：

- `no_query_observed`：由本次工具/SDK 调用和终态 trace 证明零查询；仅此不能说明后台 suppression/status/time/privacy gate 被调用。
- `zero_disclosure_observed`：核对全部实际 Provider 输入、工具返回、最终 Context 和最终答案，以及禁止来源的使用情况；必须有完整 trace，不能由零查询或空输出直接赋 true。
- `gate_exercised` 与 `gate_decision`：来自实际执行的资格/隐私/硬约束裁决事件，关联当前可信政策/状态、run/turn、原因码和结果。未走该门时标 `NOT_EXERCISED`；模型说“我遵守隐私”或 scorer 读到禁止标签均不是后台裁决证据。

hard/privacy 的正确分子只能由对应指标所要求的真实观测事实计算：若完整 trace 仅能支持端到端不披露，可如实报告该层的观测，不能据此把后台 gate 判为已测。若目标断言要求执行某个 gate，则缺少该事件时不得算通过；保留原样例/分母并标证据未闭合，不能删除样例提高分数。禁止 `correct_hard = no_query`、`correct_privacy = no_query`，也禁止用 gold 状态自动生成一份“裁决 trace”。

无查询的 S08–S11 在设计上可能根本不访问后台资格门；其不干扰/不披露证据与“检索后实际过滤”证据必须分开。后者留在独立补充协议验证，不扩入原12类质量分母。S12 的可见受众策略也只是输入前提，是否真正经过可信裁决要以 Host trace 为准。当前无真实运行，两层均未取得实测结论。
