# 迁移证据边界（2026-09-05 认定）

## 事实

本 program 从另一套系统迁移而来，迁移过程丢失了部分构建产物。实测：
6 份冻结 fixture 共钉死 **11 个 wheel 身份，磁盘上一个都不存在**。

所有 `source_commit` 仍在仓库历史里，可 checkout。从这些 commit 重建的结果是分裂的：

| 钉死的产物 | source commit | 重建结果 |
|---|---|---|
| memory 0.6.0 `723bcbc3…`（twin-graph） | `8cdc103c` | ✅ **一字不差** |
| memory 0.6.0 `cd324e68…`（typed-recall-v3） | `9c79fa7e` | ✅ **一字不差** |
| memory 0.6.0 `844cbaba…`（semantic-relations ×2） | `64284059` | ❌ 得到 `0758a92c…` |
| memory 0.6.0 `6f9a8c1a…`（sealed-audit / typed-recall-layers ×2） | `d069e0e9` | ❌ 得到 `57d20d30…` |
| harness 0.7.0 `d241052d…` | `3e7a71af` | ❌ 得到 `a0dc68f9…` |
| harness 0.7.0 `36522c4a…` ×3 | `fb491574` | 未单独验（同类） |

**两处一字不差证明构建管线本身是可复现的**；其余差异来自迁移前后的打包环境漂移
（构建工具版本等），不是源码变化，也不是证据被篡改。

## 决定（按 plan 为准 + 最佳实践，2026-09-05 用户授权自主决策）

1. **迁移前的 wheel 身份不再作为可验证锚**。它们记录的是"另一套系统上曾经构建出什么"，
   在本机不可复现，继续拿它当门禁只会把每个消费面场景永久钉死在 BLOCKED。
2. **在迁移边界重新建立基线**：需要 exact-wheel 消费面验证的场景，改为从**同一 source
   commit 在本机重建**并记录新身份；fixture 同时保留迁移前的旧身份（标注 `pre_migration`，
   仅作谱系，不参与判定）。
3. **冻结 oracle 的目的不变**：它防的是"日后无意漂移"。重新钉在本机可复现的产物上，
   这个目的完整保留；钉在一个谁也验不了的哈希上，反而是失效状态。
4. **不追溯性伪造**：任何一条"迁移前证据"都不得被表述为已验证。交付结论里如实写明
   迁移边界，以及边界之前哪些证据不可复核。

## 适用范围

REL-VALUE、SEALED-AUDIT、TYPED-RECALL 等依赖 exact-wheel 消费面的场景。
不影响任何在本机可直接执行的自动化场景（它们不依赖历史产物）。
