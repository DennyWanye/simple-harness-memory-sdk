# 基准解释与修正规则（讨论稿）

> 状态：`plan-bs` 头脑风暴中  
> 作用：记录用户对冻结原文的确认与修正；不改写原始快照

## 已确认

1. 记忆模型继续以人类认知方式为基础。
2. 记忆分类使用多个正交维度，不把认知类型、语义类别、可信状态、生命周期、作用域和隐私策略
   混入单一 `category`。
3. 世界模型纳入本次直接实施范围。
4. LLM 负责语义提取和提出标准化操作；确定性代码负责校验、幂等、冲突处理和持久化。
5. LLM 推断必须标记为推断，不得冒充用户明确事实。
6. 永久取消 L1/L2/L3 编号，使用认知类型名称。
7. Session 原始信息完整保存用于审计和复查，系统不得自动删除。

## 原始文档对三种认知记忆的定义

原始调研文档给出的区分是：

- **工作记忆**：容量小、立即可用，例子是“当前对话的上下文”。
- **情景记忆**：完整经历和对话记录，例子是消息历史、时间戳和上下文。
- **语义记忆**：从对话抽象出的知识和事实，例子是 Facts、向量索引和实体关系。

原文的接口进一步表明：完整消息先作为情景记忆保存；同一消息集合中的最近或相关部分被读取为
工作记忆。因此原设计不是三个互斥数据库，而是“完整情景历史 → 选取当前上下文”的激活关系。

## 正在讨论：工作记忆与情景记忆的产品边界

用户指出“情景记忆就是传给 LLM 的上下文”。需要进一步区分两种可能含义：

1. 情景记忆指 Prompt 中的“会话历史部分”；工作记忆指完整 Prompt 中当前被激活的全部内容。
2. 情景记忆和工作记忆在产品里应合并为同一个概念，完整 Session 只是不可删除的审计记录。

数字孪生体不是第四种原始记忆，而是由可溯源的语义记忆和情景统计生成的用户模型投影。
世界模型也不是用户记忆：它提供带来源和时效性的外部状态，在构建工作记忆时与用户记忆汇合。

- “Session 不可以删除”是否也包括用户本人明确要求删除，还是仅禁止系统自动删除和物理清理。
