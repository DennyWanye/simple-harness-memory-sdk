已有持久列足以恢复并核验 **创建目标 revision 的 signal apply 来源**，不需要先加 schema；不能恢复未存的上游 receipt 全文，也不能据此证明当前 outbox 的生成 cause。

三种凭据必须区分：① `intent.signal_receipt_id/hash` 是当时Host提交并被authority绑定的**上游输入凭据引用**，SDK没保存它的完整正文；② consumption/decision证明SDK实际消费与裁决；③ `ProspectiveSignalApplyResult.result_id/result_hash` 是SDK持久的**应用结果**，可作为后继引用目标revision产物的凭据。③不能改装成 MemoryMutationApplyReceiptRef，①不能冒充③。

## 最小 public/Host 兼容形状

保留616方法及v1 DTO/hash行为。已新增：

```python
await memory.read_prospective_outbox_source_v2(
    principal=principal, outbox_id=entry.outbox_id, payload_hash=entry.payload_hash,
) -> ProspectiveOutboxSourceViewV2
```

共同字段保留 subject、确切outbox ID/payload hash/created_at、command、target memory/revision/registration_revision、target scope/task_scope/lifecycle、trigger/hash、outbox_cause_status。采用显式 `target_source` 判别联合：

- `kind="mutation"`：真实mutation receipt ref、plan ID/hash、原run/operation/kind；可复用616已核事实。
- `kind="prospective_signal"`：真实 `apply_result: ProspectiveSignalApplyResult`，历史signal_id/kind、intent_hash、authority_id/hash/ref_hash、consumption_id/hash、decision_id/hash，以及上游signal_receipt_id/hash、intent.run_id/operation_id。不返回可执行authority/grant，不填mutation receipt或synthetic mutation plan。

V2的事实JSON/hash用独立v2域；`operation_observation`仍独立于事实hash、相等比较，成功/拒绝/取消沿616 metadata交接规范。Host显式选v2，不在v2损坏/限额拒绝时偷偷降级v1。

Host现 `prospective_registration_source.py:85` 只有mutation receipt选择：改为显式分支。mutation来源沿用真实mutation receipt；signal来源以 **apply_result.result_id/result_hash** 作为后继ACK的 signal_receipt_id/hash，run/op取该已消费intent原值，outbox ID/hash和created_at仍独立核对。这只声明目标来源，不能称其生成了本次invalidation。Memory里的run/op是已消费Host authority所承诺的历史值；是否对应真实Harness Run/operation由Host公开入口核验，不能由SDK补造Run。

## 必须验证的确切链

从确切outbox定位目标历史revision，在SDK内部以目标memory、committed_revision、owner筛选 `outcome=applied` 的decision并连接consumption/result，要求唯一；零条明确unavailable，多条或绑定不符拒绝。保留616单文档/SQL步数预算，无索引时超限直接失败，不为猜测新建表或索引。

必须联核：authority/ref规范hash与重复列；consumption hash；decision/result规范hash、consumption/result/decision引用；result.committed_revision恰等于目标revision且base+1；signal确实APPLIED而非ACK/IGNORED；输入base revision生命周期=intent.transition_from，目标历史生命周期=result.lifecycle_state=intent.transition_to；目标revision的synthetic trace/operation与该authority/intent精确相符；owner/scope、继承task_scope/content/trigger与输入历史revision一致。synthetic ID算法只由SDK内部核，不交给Host复制。

到今天已过期的authority仍可作为曾在有效期内consumed的历史事实读取；历史消费时限须核。不能使用当前head、今天时钟或created_at猜选某一Run/operation；读取不重新签发旧authority。

## source补齐后仍不可伪过的现有门

`sqlite_v5.py:9606` 仅对PENDING/RESCHEDULED发registration；TIME_DUE实际产生TRIGGERED revision时不自动给新revision登记registration。之后真实REVISE会为该live旧revision发invalidation，而 `:9997` 的SDK live registration检查与Host `prospective_registration_source.py:69` 均要求**该确切revision真实accepted registration**。

因此，恢复signal source能解决receipt来源缺口，但不能把从未注册的新revision伪装成已注册；尤其不能挪用更旧revision的registration_ref满足门。后继真实链若遇到这一路径，需明确处理“没有相应registration的invalidation命令”语义，不能以reader成功冒称scheduler闭合。本轮只记录这一已有实码约束，不擅改出队/ACK/schema。

只新增signal来源公开正反控，不重复616已绿套件或旧制品扫描；结果见文末。

## Hegel 固定 DTO 与 observation 接缝

以下类型均从 `simple_harness_memory` 根导出。Host按显式operation精确调用，无fallback。

| 根类型 | 固定字段 |
| --- | --- |
| ProspectiveOutboxSourceViewV2 | schema_version=2；共同字段见下方；target_source为严格联合 |
| MutationTargetSource | kind=mutation；mutation_receipt_ref、plan_id、plan_hash、run_id、operation_id、operation_kind |
| ProspectiveSignalTargetSource | kind=prospective_signal；apply_result、signal_kind、intent_hash、authority_id/hash、authority_ref_hash、consumption_id/hash、decision_id/hash、upstream_signal_receipt_id/hash、run_id、operation_id |
| ProspectiveSourceReadObservationV2 | 沿616观察结构，operation严格为read_prospective_outbox_source_v2，schema_version仍为1 |

`ProspectiveOutboxSourceViewV2.to_json()` 恰包含：schema_version、subject、outbox_id、outbox_payload_hash、outbox_created_at、command、target_memory_id、target_revision、registration_revision、target_scope（kind/owner_id）、target_task_scope_id、target_lifecycle_state、trigger、trigger_hash、target_source、outbox_cause_status。

target_source按分支to_json编码；signal分支的apply_result为既有ProspectiveSignalApplyResult，另编码apply_result_hash，因为原ApplyResult.to_json不含派生hash。不提供旧版顶层target_run_id/target_mutation_receipt_ref，Host显式读取target_source分支。source_hash域为 `memory.prospective.outbox.target-source.v2`，payload为上述to_json。operation_observation不纳入to_json、source_hash或事实相等比较；v1保持原样。

`ProspectiveSourceReadObservationV2.to_json()` 恰包含：

```text
invocation_ref_hash, request_hash, claimed_owner_ref_hash, source_hash,
outcome, reason, observed_at, operation, persistence_status, schema_version
```

派生observation_hash不在to_json中。成功值通过source.operation_observation交付；拒绝/取消通过原异常.operation_observation交付。observed_at为实际物理观察时间，不是outbox或原signal发生时间；persistence_status固定host_persistence_unverified，Host单独记录journal落盘状态。

| hash | 域 | payload |
| --- | --- | --- |
| observation_hash | memory.prospective.source.observation.v2 | observation.to_json() |
| request_hash | memory.prospective.source.request.v2 | [outbox_id, payload_hash]，SDK生成 |
| claimed_owner_ref_hash | memory.prospective.source.claimed-owner.v1（沿v1） | [deployment_id, household_id, actor_id, session_id] |
| invocation_ref_hash | memory.prospective.source.invocation.v2 | 本次SDK调用生成的UUID字符串 |

沿既有 `_hash(domain, payload)`：对 `{domain, payload}` 做ensure_ascii=False、sort_keys=True、separators=(",", ":")、allow_nan=False的JSON UTF-8 SHA-256。无法安全有界编码的输入对应request/owner hash允许None，Host不能补造。success观察的source_hash等于实际返回source.source_hash，其他outcome为None。

outcome/reason沿616有限集合：observed/source_verified，rejected/{input_or_binding_rejected,ownership_rejected,source_corrupt,resource_limit}，failed/source_read_failed，cancelled/source_read_cancelled。Host request/caller身份纳入operation，与public observation.operation精确匹配。复用原Host journal，SDK只投影既有白名单fingerprint/stage/to_state/state_version；不新建表/账本，不把日志可见称作持久审计成功。

## 未注册 revision 的 invalidation：交主决定的方案

待取消身份始终是原命令的 **memory_id + target_revision + registration_revision + trigger_hash**；已ACK时再绑定真实scheduler_registration_ref。不用run、当前head或最近ref替换。

| 实际状态 | 必需语义 |
| --- | --- |
| 存在该revision的registration请求，但尚未ACK | 不是not-required。持久记录对确切请求的依赖，先完成原登记再对同revision取消；或另定有记录的原子撤销协议。若invalidation先被队列读到，须有界处理该依赖，不能永久轮询队首或无记录跨过cursor。 |
| signal派生revision从未有registration请求 | 该revision没有对应scheduler登记可取消。例如r1登记，TIME_DUE创建r2=TRIGGERED时已产生invalidation(r1)，未产生registration(r2)；后续REVISE创建的invalidation(r2)不能借用r1 ref。原r1取消义务仍由原invalidation(r1)独立完成。 |

**未来emit建议**：以确切registration请求是否真实存在为依据，不能只看accepted状态。有请求的revision仍需发取消；对已核signal派生链且从未发过请求的revision，不再产生无对象的invalidation。保留r1→r2时对r1登记的取消义务；不把其他异常缺行泛化成可跳过。

**已有outbox建议**：保留旧payload/ID/hash。公开给出最窄、可核验的“目标确为该signal派生revision且确切registration请求从未存在”事实；Host推进cursor前，持久记录not_required终局，绑定owner、旧outbox ID/hash、target source hash、取消身份和无请求事实。它不是SDK registration_invalidated ACK，也不是Memory mutation receipt。损坏、限额、无法证明的缺行不能not_required；有请求未ACK必须走依赖路径。若要求SDK自身持久签发终局receipt，再由主另定存储合同，本叶不造schema或假receipt。

以上为消除遗留队首阻塞的建议，尚未实施；本叶仅完成来源读取，不宣称scheduler全链闭合。

## Carver lostACK：复用公开apply

本次已验证真实public signal提交后，保存原ProspectiveSignalAuthorityRef，重开后即使authority过期、未配置resolver，再调 `apply_prospective_signal(principal=..., scope=..., reference=原ref)` 会先核持久replay链，返回原ProspectiveSignalApplyResult，result_id/hash不变。未提交的过期ref没有结果可恢复，仍走正常拒绝；不能推测已提交、换ref或续期伪装重放。不为lostACK另增reader。
